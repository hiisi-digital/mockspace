# Why this round exists

token-scan lints (no-std, no-alloc, no-dyn-dispatch, no-runtime-*) scan for literal tokens OUTSIDE strings and comments. They carry a variable-length token list (the variable-config arm) and run a strip pass before matching. A no_std / no_alloc cdylib cannot allocate the blanked-copy view the in-process `strip` produces, so the port skips strip-spans during a per-token scan instead of blanking them.

# What lands

A `no-std` provider (`mockspace-builtin.lint.no-std.v2`), a shared `token_scan_core` (future token-scan lints add a thin wrapper + provider reusing it), a length-prefixed config-blob decoder, and a strip-span detector ported from `mockspace_rs::strip` (line + block comments with doc distinction, plain + raw strings, honouring the per-lint strip flags). Unit tests cover live-code matching, string / comment / raw-string skipping, strip-flag-off behaviour, multi-token, word boundary, the empty + malformed config paths, and overflow.
