## Crate layout: the cdylib pack is its own workspace root

The cdylib links the stack (arvo / hilavitkutin-extensions / viola-plugin-abi), a dependency universe disjoint from the mockspace tool crates (which pin tree-sitter and run on std). It lives at `mock/crates/mockspace-builtin-lints/` per the DOC CL's flat-layout claim, but it is NOT a member of the mockspace tool workspace: it declares its own `[workspace]` table and the tool workspace excludes it. This isolates the two dependency graphs (the PR #212 tree-sitter-at-workspace-level conflict cannot arise) and keeps `cargo mock check` from compiling the stack.

The crate's `[dependencies]` use the SAME source specs as viola's `[workspace.dependencies]` (ssh scheme, `branch = "dev"`, `default-features = false`). PR #212 used https specs against viola's ssh specs; to cargo those are distinct sources, so arvo resolved twice and `arvo::USize` would not unify at the vtable boundary. Matching the specs lets cargo deduplicate the cdylib's direct arvo against viola-plugin-abi's transitive arvo to one crate. This resolves the PR #212 blocker without a `[patch]` table.

### CHANGE: fn `no_todo_evaluate` ADDED (cdylib evaluator for the no-todo lint)

File: `mockspace/mock/crates/mockspace-builtin-lints/src/lib.rs`

```rust
unsafe extern "C" fn no_todo_evaluate(
    host_ctx: *mut c_void,
    nam: *const NamPayload,
    lint_config_bytes: *const u8,
    lint_config_len: arvo::USize,
    out_entries: *mut Diagnostic,
    out_capacity: arvo::USize,
    out_len: *mut arvo::USize,
) -> AbiStatus;
```

v2 host-owned-buffer shape (Decision 1 / Option B): the host owns `out_entries`. Body walks the NAM v1.x file entries (via `viola_plugin_abi::nam_file_entries`), runs a word-bounded scan for the marker token per file (mirroring the `\bTODO\b` regex of the in-process `ContentRegexLint`), and writes one `Diagnostic` per match into `out_entries` up to `out_capacity`. It sets `*out_len` to the count it would have emitted and returns `AbiStatus::Internal` when that count exceeds `out_capacity`, else `AbiStatus::Ok`. Returns `AbiStatus::InvalidArg` when `out_len` is null or the NAM payload is not v1.x. The scan core is factored into a pure `for_each_match` helper with unit tests; the plugin keeps no state across calls.

Verification: `grep "fn no_todo_evaluate" mockspace/mock/crates/mockspace-builtin-lints/src/lib.rs` returns one match.

## Test harness CHANGE blocks

### CHANGE: unit tests ADDED (`#[cfg(test)] mod tests`)

File: `mockspace/mock/crates/mockspace-builtin-lints/src/lib.rs`

In-crate unit tests rather than a separate `tests/` integration file: a cdylib's `tests/` would need a viola host loader (viola-core machinery) that does not exist in this isolated workspace, while the contract is fully exercised by calling the evaluator and the pure scan core directly. `#[cfg(test)] extern crate std;` provides the test harness; the panic handler / eh-personality / libc-link items are `#[cfg(not(test))]`.

Coverage:
- pure `for_each_match`: single match line/column, multiple-match line/column tracking, `\b` word-boundary corners (trailing and leading word bytes both reject), case-sensitivity (lowercase does not match).
- the FFI `no_todo_evaluate`: writes diagnostics into a host buffer and reports `out_len`; reports `AbiStatus::Internal` with the would-have-emitted count on overflow (capacity 1, two matches); returns `AbiStatus::InvalidArg` on a null `out_len`.

Verification: `cargo test` in `mockspace/mock/crates/mockspace-builtin-lints/` passes (7 tests).
