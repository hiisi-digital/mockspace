## What this round commits

The DOC CL accompanying this topic commits:

1. **Path A directional commitment** (R0): mockspace lints become viola plugins exporting the existing `viola.lint.evaluate.v1` vtable; mockspace's `LintEngine` trait gains a `ViolaEngine` impl translating between `Document`/`Finding` and `NamPayload`/`DiagnosticBatch`. `MockspaceEngine` placeholder at `mockspace-rs/src/engine.rs:30` stays for the transitional window.

2. **NAM v1.0.0 minimal schema** (R1): per-file entries carrying `path: BytesRef`, `language: arvo::USize`, `source: BytesRef`. Alternative (parallel `viola.lint.evaluate-raw.v1` vtable) rejected on protocol-coherence grounds.

3. **DiagnosticBatch fixed-cap with overflow status** (R2): 256 slots per call, `AbiStatus::Internal` returned on overflow. Retry protocol deferred.

4. **Reused viola host_ctx** (R3): mockspace lints treat the host_ctx opaque; cross-cutting host state flows through NAM's `run_context` block.

5. **Per-lint provider ids** (R4): `<pack>.lint.<name>.v1` shape; N entries per descriptor. `MAX_DESCRIPTOR_LIST_LEN = 1<<20` covers per-lint table size. Per-pack-with-internal-routing alternative rejected on enumeration, dispatch, and observability grounds.

6. **Transitional cdylib-load config** (R5): `mockspace.toml [plugins]` during transition; migrates to `viola.toml` per task #200 once viola integration lands.

7. **First-port lint scope**: `no-todo` ports as the pattern reference. The cdylib lives at `mockspace/mock/crates/mockspace-builtin-lints/` (flat layout per the existing convention). The descriptor exports one `ProviderEntry` whose `provider_id = ProviderId::from_name("mockspace-builtin.lint.no-todo.v1")` and `vtable_ptr` points at a `LintEvaluateVtable` static. The evaluator function reads source bytes from the NAM payload via the v1.0.0 schema, runs the regex scan currently in `mockspace-rs/src/builtins/content_regex.rs:124`, and writes one `Diagnostic` per match into the host-provided `DiagnosticBatch`.

## LOAD-BEARING op confirmation points

The DOC CL ships with two resolutions flagged as agent's call rather than op-confirmed:

- **R1 NAM schema**: agent picked option 1 (minimal forward-extensible schema) over option 2 (parallel raw-source vtable) on protocol-coherence grounds. If op prefers option 2, the DOC CL deprecates and a replacement ships option 2.
- **R4 per-lint provider id**: agent picked per-lint over per-pack on enumeration, dispatch, and observability grounds. If op prefers per-pack with internal routing, the DOC CL deprecates and a replacement ships per-pack.

Both are revealed in the DOC CL itself with explicit reasoning, so op can redirect on review of the DOC CL as readily as on a memo. The deprecate-and-replace cost is one extra round if redirection is needed.
