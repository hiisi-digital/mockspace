# DOC CL: lint catalog onto the WorkUnit-cdylib boundary

**Round:** 202605251600
**Phase:** DOC
**Scope:** Workspace task #610. Commits the design surface for porting the mockspace lint catalog onto the cdylib boundary landed under task #609.

## R0: Path A directional commitment

Mockspace lints become viola plugins. Each lint cdylib exports the existing `viola.lint.evaluate.v1` vtable shape (defined at `viola/mock/crates/viola-plugin-abi/src/vtable.rs:102`). Mockspace's `LintEngine` trait (at `mockspace-core/src/lint.rs`) gains a `ViolaEngine` impl that routes mockspace lint dispatch through viola's plugin host.

Translation between `mockspace_core::lint::{Document, Finding}` and `viola_plugin_abi::{NamPayload, DiagnosticBatch}` happens host-side inside the `ViolaEngine::run` body. Cdylibs see only the viola wire types; mockspace's vocabulary stays insulated from the cdylib boundary.

`MockspaceEngine` placeholder at `mockspace-rs/src/engine.rs:30` stays for the transitional window. Deletion is post-viola-integration (task #198) and out of scope for this round.

Rejected: Path B (mockspace ships its own parallel vtable). Reason: protocol coherence (one boundary across mockspace + viola) outweighs vocabulary fidelity (cdylib boundary uses viola types; mockspace types translate at the host boundary).

## R1: NAM v1.0.0 minimal schema [LOAD-BEARING]

NAM v1.0.0 ships with a minimal forward-extensible schema. The opaque `NamPayload` carrier (defined at `viola/mock/crates/viola-plugin-abi/src/nam.rs:34`) gains a documented v1.0.0 schema for its `data` pointer: a slice of per-file entries, each carrying:

- `path: BytesRef` (workspace-relative path).
- `language: arvo::USize` (language tag matching `mockspace-core::lint::Language` discriminants; the integer value identifies the language; the in-memory carrier uses `arvo::USize` per `no-bare-primitives.md`).
- `source: BytesRef` (UTF-8 source bytes; plugin-owned static for the call's duration).

Lints accessing parsed structure (no-duplicate-fn, undocumented-type) wait for a v1.1+ NAM schema revision that adds extracted structure. The DOC CL commits the v1.0.0 minimal shape; v1.x richer schemas land as separate rounds.

The concrete `#[repr(C)]` wire-struct shape (field ordering, alignment, padding) is deferred to the SRC CL slice that ports no-todo. The DOC CL commits the v1.0.0 slot list (`path: BytesRef`, `language: arvo::USize`, `source: BytesRef`) and leaves the wire shape's mechanical encoding for the SRC CL to fix when the cdylib lands. Op confirmation on R1 is about the slot list and protocol choice, not the wire struct's byte layout.

Rejected: parallel `viola.lint.evaluate-raw.v1` vtable. Reason: fragments the cdylib protocol; option 1 keeps one boundary and grows the schema as needed.

**Op confirmation point**: the minimal-schema vs parallel-vtable choice is the load-bearing call. If op prefers option 2 (parallel vtable), this DOC CL deprecates and a replacement ships option 2's shape.

## R2: DiagnosticBatch fixed-cap with overflow status

`DiagnosticBatch` is a fixed-cap output buffer with 256 slots. When the evaluator function fills the buffer, it returns `AbiStatus::Internal` and stops emitting further diagnostics for that call. The host treats `Internal` status as a non-fatal warning and continues to the next lint.

Retry-with-fresh-batch protocol is deferred to a later slice when a real workload pressures the cap.

## R3: Reused viola host_ctx

The `host_ctx: *mut c_void` argument of `LintEvaluateVtable::evaluate` is the viola-shaped host context. Mockspace lints treat it as opaque. Cross-cutting host state (workspace root, run surface, CI flag) reaches lints through NAM's `run_context` block (per `viola-plugin-abi/src/nam.rs` module doc reference to NAM §9.3).

No mockspace-specific host_ctx shape needed. Forking host_ctx between viola and mockspace lints would be a second boundary divergence after the protocol unification just committed.

## R4: Per-lint provider ids [LOAD-BEARING]

Each ported lint gets a distinct provider id namespaced by pack origin:

- mockspace built-in pool: `mockspace-builtin.lint.<name>.v1`
- stack-lints pool: `stack.lint.<name>.v1`
- per-repo lints: `<repo>.lint.<name>.v1`

One cdylib hosts N entries in its descriptor `providers` table. Each entry's `vtable_ptr` points at a distinct `LintEvaluateVtable` static. The host walks `ProviderEntry[]` once at load time and learns each lint's existence from the descriptor directly.

`MAX_DESCRIPTOR_LIST_LEN = 1<<20` (per `hilavitkutin/mock/crates/hilavitkutin-extensions/src/descriptor.rs:45`) trivially covers the per-lint table size for the 16+17+repo-local catalogue.

Rejected: per-pack provider id with internal routing. Reason: per-lint shape gives the host descriptor-time enumeration of available lints, stable function pointers per lint (LLVM can de-virtualise or inline through them), and legible backtraces/profiles naming individual lints.

**Op confirmation point**: per-lint vs per-pack is the second load-bearing call. If op prefers per-pack with internal routing, this DOC CL deprecates and a replacement ships per-pack.

## R5: Transitional cdylib-load config

During the transition between mockspace's in-process `MockspaceEngine` and viola integration:

- New `[plugins]` section in consumer `mockspace.toml` lists cdylib paths.
- `ViolaEngine` reads `[plugins]` to discover which cdylibs to load.
- `MockspaceEngine` placeholder ignores `[plugins]` (it loads via the existing `[lint-crates]` mechanism).

Post-viola-integration (task #200): config migrates to `viola.toml`. The `[plugins]` section in `mockspace.toml` deprecates alongside the rest of mockspace's lint config.

This is mechanical: `mockspace.toml [plugins]` is additive to existing config, and viola.toml migration ships when viola integration is ready.

## First-port lint: no-todo

The cdylib crate lives at `mockspace/mock/crates/mockspace-builtin-lints/` (flat layout matching the existing `mock/crates/<name>/` convention; no `lints/` sub-grouping). Its `Cargo.toml` shape:

```toml
[package]
name = "mockspace-builtin-lints"
version = "0.0.0"

[lib]
crate-type = ["cdylib"]

[dependencies]
hilavitkutin-extensions = { git = "https://github.com/orgrinrt/hilavitkutin.git", branch = "dev" }
hilavitkutin-extensions-macros = { git = "https://github.com/orgrinrt/hilavitkutin.git", branch = "dev" }
viola-plugin-abi = { git = "https://github.com/hiisi-digital/viola.git", branch = "dev" }
arvo = { git = "https://github.com/orgrinrt/arvo.git", branch = "dev" }
notko = { git = "https://github.com/orgrinrt/notko.git", branch = "dev" }
```

The crate body declares:

- One `LintEvaluateVtable` static per ported built-in lint (16 statics total for the built-in pool).
- One evaluator function per lint, named `<lint_name>_evaluate`.
- One descriptor static (via `#[hilavitkutin_extensions_macros::export_extension]`) listing all 16 provider entries.

For `no-todo` specifically, the evaluator function:

1. Reads `nam: *const NamPayload` and resolves source view via the v1.0.0 schema accessors (defined in `viola-plugin-abi` per R1).
2. Reads `lint_config_bytes: (*const u8, arvo::USize)` (empty for no-todo, which has no tunable parameters).
3. Walks the regex pattern `\bTODO\b` over the source view.
4. For each match: writes a `Diagnostic` into `out_batch` with `(lint_name = "no-todo", path, line, column, length, message = "todo found in shipped source", severity = Warn)`.
5. Returns `AbiStatus::Ok` on success or `AbiStatus::Internal` on batch overflow.

The body translates the in-process `ContentRegexLint::check_document` body at `mockspace-rs/src/builtins/content_regex.rs:124` mechanically; the pattern detection logic is unchanged.

Test harness: `viola-plugin-abi`'s existing test fixtures (per task #562 `mockspace-test-fixtures`) cover cdylib load + vtable dispatch. The no-todo test asserts: (a) descriptor exports the expected provider id, (b) evaluator emits the expected diagnostic for a known source input, (c) evaluator returns `Internal` when the batch is full.
