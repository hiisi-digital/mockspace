# Topic: under sudo, the bootstrap installs as the invoking user instead of skipping

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `bootstrap_from_buildscript()` guard B from round `202607190741`, replaced. Guard A (cargo-cache
skip) is untouched.
**Supersedes:** the guard B decision in `202607190741/202607190740_topic.bootstrap-cache-guard.md`.

## Op's correction

Round `202607190741` shipped guard B as warn-and-skip under sudo. Op rejected the vehicle: the bootstrap is
how the mockspace safeguards (hooks, gates) get installed, so any skip path leaves a repo in the one state
mockspace exists to prevent, working without its safeguards. That state was demonstrated live the same hour:
vehje took an ungated commit because its hooks directory had been deleted along with `target/`. A bootstrap
that "fails open" is not tenable. The instruction: find a way to do it that is good, not a way to not do it.

The distinction that governs this round: **failing open** (skip, warn, continue unguarded) is forbidden;
**failing closed** (the build itself refuses to proceed) is acceptable as a last resort; **succeeding
correctly** is the requirement wherever possible.

Guard A survives because a cargo-cache checkout has no safeguards to lose: nobody commits from
`~/.cargo/git/checkouts/`, and the consumer's working repo receives its own hooks from its own `build.rs`.
Skipping there prevents pollution and forfeits nothing.

## Decision

Under sudo the bootstrap **proceeds and then repairs ownership**. sudo publishes the invoking user's
identity as `SUDO_UID` and `SUDO_GID`; root may chown; so the install runs in full and every path the
bootstrap owns is chowned to the invoking user afterwards. The safeguards land, correctly owned, and the
poison mechanism from the 2026-06/07 incident is converted into a correct install.

The ownership repair covers exactly the bootstrap's output roots: `<repo>/.cargo` (recursive),
`<repo>/target` (the directory entry only, since bootstrap may create it), `<repo>/target/mockspace-proxy`
(recursive), `<mock>/target` (entry only), `<mock>/target/hooks` (recursive), and `<repo>/.gitignore` (entry).
The consumer's wider `target/` tree is cargo's output, not the bootstrap's, and is out of scope.

**Fail closed on the residue.** If `SUDO_USER` is present but `SUDO_UID`/`SUDO_GID` are missing or
unparseable, or any chown in the repair fails, the build script panics with a message naming the problem and
the remediation (run the build without sudo). A failed build blocks all work with safeguards intact, which
is categorically different from a skipped bootstrap permitting unguarded work.

Non-unix targets compile the sudo path out (`cfg(unix)`); the sudo environment contract is unix's.

## Also in scope: the review finding from PR #264

The reviewer found guard B untested and the cargo-home resolution untested, both unreachable inline. This
round extracts `resolve_cargo_home(cargo_home_env, home_env)` and `parse_sudo_ids(uid_env, gid_env)` as

## Not in scope, named as the follow-up this correction exposes

The hooks themselves fail open: `core.hooksPath` points under `target/`, so deleting `target/` silently
disables every gate (the vehje ungated commit). The good shape is a thin shim installed to `.git/hooks`
that survives target cleans, re-bootstraps the proxy when missing, and **blocks the commit when it cannot
validate** instead of passing. That is its own round; this topic records it so it is not lost.
