# Topic: a durable agent-side gate in the generated hooks

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `src/render_agent.rs`. A fifth builtin agent hook, `mockspace-gate.sh`, written to `.claude/hooks/`
and `.github/hooks/` alongside the four existing ones.
**Motivation:** op, 2026-07-19. The durable git gate (round `202607191001`) closes the terminal-commit path.
This closes the agent-commit path, natively in mockspace rather than in the workspace aggregation layer,
which is op's homma concern and not native mockspace.

## Decision

The generated agent hooks live in `.claude/hooks/`, which persists across a `target/` clean. Add a builtin
hook that fires on `Bash` and, for a `git commit` or `git push`, verifies the gate machinery is intact
before allowing:

1. `_scope_or_allow`: only this repo's tool calls.
2. match `git ... commit|push`; anything else is allowed.
3. gate intact when BOTH the live validator (`<root>/<mockdir>/target/hooks/pre-commit`) is executable AND
   `core.hooksPath` is wired to a mockspace dir. Intact -> allow (the real git hook then lints).
4. broken -> self-heal (`cargo check` in the mock dir re-runs the bootstrap, regenerating the validator and
   re-activating `core.hooksPath`), re-check.
5. still broken -> deny, blocking the agent commit/push with the restore command.

This is the same self-heal-then-block contract as the git hook, on the agent side, and it additionally
catches the case the git hook cannot: `core.hooksPath` unset (a fresh clone) where git would run no hook at
all but `.claude/` proves mockspace was generated here at least once.

## Not in scope

The workspace-level `_workspace--mockspace-gate.sh` aggregation hook. That is op's homma/workspace layer,
not native mockspace, and is the wrong side to fix this on (op, 2026-07-19).
