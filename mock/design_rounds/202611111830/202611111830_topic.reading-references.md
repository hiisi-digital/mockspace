# Reading references

The topic of 11 November on the files of a shared directory on a ref (`202611110830_topic.files-of-a-shared-directory-on-a-ref.md`) carried, beside its own subject, how the engine reads a reference under the letkajenkka standard. Reading a reference is no part of what a ref holds, so it stands here as a topic of its own, and the migration that rewrites the older spelling stays where it was, among the named migrations.

## Resolving

A pass that resolves many citations opens a scope in which each directory a citation walks through is listed once. Nothing is held outside a scope, so a file made between two passes is found.

## Names and lists

The standard leaves the fold of a host's own naming to the host, and requires the host to make it and to accept no unfolded spelling (`SPEC.md` of letkajenkka, §3.2). Mockspace folds a name into the standard's character set itself, the same way in both of its workspaces, so `mock::design` reaches a file called `DESIGN.md`. A list of references is split at the commas of its own level by the syntax.

Nothing in the engine cuts a reference at its separator. The one reader of the spelling before the standard is the migration's, and the gate below asks it rather than reading that spelling a second time.

A code fence holds no reference. A fence opens on a line of three or more backticks, or three or more tildes, and closes on a line of the same character at least as long, with nothing after it, and every reader of a document skips fences by that one rule.

## Headings

A heading is anchored as the slugger GitHub follows anchors it (`mock/research/202611111500_github-heading-anchors.md`): lowercased, then every character deleted but the space, the hyphen, anything alphabetic, the marks, the decimal digits and the connector punctuation, and then each space one hyphen, with no collapsing and no trimming.

## Which run a reference that resolves to nothing stops

What follows is provisional. It stands on a stamp, pending op's answer on question ticket bb6adc744076, and his answer can change it.

A reference the standard reads, into a declared namespace, gates the run that changes the template holding it, as a row citing a missing row does. A text the standard refuses, which the reference migration reads as a reference to a row in the spelling before the standard and would rewrite, keeps that same scope, the one it had before the standard; its namespace is read by the migration's own reader of that spelling. Every other text the standard refuses gates every run, as does a reference to anything but a row, and every reference of a document generated from no template. A finding that holds a text the standard refuses says that `cargo mock migrate references-to-letkajenkka` rewrites a repository written in the older spelling.
