# Topic: durable-gate review fixes (PR #265)

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `src/bootstrap.rs`, `src/render_agent.rs`. Four correctness fixes from the senior review of PR
#265.

## Findings and fixes

1. **Re-activation loop on a durable-write failure.** `hooks_path_target` returns `durable_hooks_dir()`
   unconditionally when HOME is set, but `activate` falls back to the generated dir when the durable dir is
   not writable. If the durable dir is resolvable-but-unwritable, `activate` sets `core.hooksPath` to the
   generated dir while `check_activation` expects the durable dir, so it re-activates and logs a spurious
   update on every build. Fix: `hooks_path_target` returns the durable dir only when it exists (was created);
   `activate` uses the same `hooks_path_target` rather than its own fallback, so the two always agree.

2. **Agent-gate git-command regex over-matches.** `\bgit\b.*\b(commit|push)\b` matches read-only commands
   like `git log --grep=commit`, `git config commit.gpgsign`, `git help commit`. When the gate is broken
   these trigger a self-heal and deny, contradicting pass-through. Fix: anchor the verb to the git subcommand
   position, matching `git commit` / `git push` and `git -C <dir> commit|push`, not any later occurrence.

3. **Self-heal `cargo check` can rewrite `Cargo.lock`.** A stale lock lets cargo rewrite it mid-commit,
   dirtying the tree. Fix: `cargo check --locked` in both the git-hook and agent-hook self-heal, so a lock
   change fails the heal (fail closed) rather than mutating the tree.

4. **`activate` discards durable-write diagnostics.** The local `actions` vec from `ensure_durable_hooks` is
   dropped. Fix: forward those messages to stderr.

## Not in scope

Behavioural change beyond these four. The gate contract is unchanged.
