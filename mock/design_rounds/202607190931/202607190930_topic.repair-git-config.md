# Topic: sudo repair must also return .git/config ownership

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `repair_ownership` in `src/bootstrap.rs`. One repair root added.
**Trigger:** PR #264 senior review, correctness finding.

## The gap

The sudo ownership repair chowns six output roots but not `.git/config`. During bootstrap,
`check_activation` calls `activate`, which runs `git config --local core.hooksPath <dir>`. git rewrites the
config through a lock-and-rename; under sudo that leaves `.git/config` root-owned. The repair then succeeds
loudly on its six roots and silently leaves `.git/config` root-owned, reintroducing the exact EPERM class
the round exists to prevent: every later unprivileged `git config --local` (each stale-activation update,
any other local config write) fails with permission denied.

Verified in source: `check_activation` (`src/bootstrap.rs:1204`) calls `activate` (`:1233` on stale-path
update, and the auto-activate fall-through), and `activate` (`:252`) runs `git config --local`.

## Decision

Add `.git/config` as a seventh, non-recursive repair root, resolved through the existing `resolve_git_dir`
so a worktree or submodule `.git` file is followed to the real git directory rather than assuming
`repo_root/.git/config`. Chown the single `config` file with `lchown`; never chown `.git` recursively, which
would touch objects, refs, and the user's own history unnecessarily and dangerously.

## Not in scope

Broader `.git` ownership. Only `config` is written by the bootstrap; the rest of `.git` is the user's and
predates the sudo build.
