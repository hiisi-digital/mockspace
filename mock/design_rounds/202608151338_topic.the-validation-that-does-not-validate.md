# Topic: the validation that does not validate

**Date:** 2026-08-15
**Phase:** TOPIC
**Scope:** `bench-harness/src/validation.rs`, `bench-harness/src/driver/mod.rs`, `bench-core/src/lib.rs`, `bench-harness/src/matrix.rs`
**Source:** two expert investigations on branches `docs/sweep-investigation` and `docs/sweep-consumer-view`

This round exists because a framework that exists to decide questions by measurement has been
producing measurements nobody checked. The layout and vocabulary work that prompted the
investigation is a separate subject and has its own topic file; this one is first because every
number in the committed artifact trail was produced under the defects below.

## What was found

**The fidelity digest is computed, carried across the FFI boundary, written into the CSV, and never
compared.** The string `digest` does not occur in `bench-harness/src/validation.rs` at all. Commit
`2471643`'s message states that the cross-variant check reads it. The check reads the reps-variant
output bytes instead (`validation.rs:501`), and `timed_calibrated!` makes those bytes
rep-count-dependent (`bench-core/src/lib.rs:596-604`), so the quantity being compared is not the
quantity the design intended and varies with calibration.

**A cross-arm mismatch drops nothing.** `validate` returns `Err` on any mismatch
(`validation.rs:525-537`). The driver's `Err` arm leaves `variant_paths` untouched
(`driver/mod.rs:415-418`), so a disagreeing arm stays in the comparison and its numbers reach the
report and the ledger. Only `required = true` affects the exit code, and **no consumer sets it**:
across 259 sections in the workspace, `required`, `may_differ` and `timing` are each used zero
times while all three are in the schema.

**Generated benches cannot express the keys that would have changed that.**
`render_bench_section` (`matrix.rs:285-308`) emits no `may_differ`, no `required`, no `threaded`
and no timing override, so every generated bench silently takes defaults. For the largest consumer
that is 135 of 180 sections.

**And one consumer hand-wires the check the framework should own.** arvo wires validation at
`main.rs:134-144`, carrying a note that an off-by-one there once "produced 400 rows of
ordinary-looking numbers and exit 0". hilavitkutin wires neither validation nor the disasm check.
The same defect class was found and fixed upstream earlier in this arc, where fourteen bench
crates had validators that never executed, so this is the second instance of the same shape.

## Why this is one subject

Each of the above is a different mechanism, and they compose into one property: **a wrong answer
survives the pipeline and is indistinguishable in the artifacts from a right one.** The digest
would have caught it and is not read; the mismatch path would have caught it and drops nothing;
the manifest keys that would have made the drop fatal cannot be written by the generator; and the
one consumer that noticed wired its own check by hand and recorded that its first attempt was
wrong.

## What this topic must settle

- What the digest is for, and whether comparing it is the right check or a redundant one now that
  the reps-variant path exists. Either it becomes load-bearing or it stops being carried.
- What a validation failure does. Dropping the arm, failing the run, and recording the verdict are
  three different responses and the framework currently does the fourth, which is nothing.
- Whether `required` defaulting to false is the right default for a measurement tool, given that
  no consumer has ever set it and the effect of the default is that failures are advisory.
- What the generator must be able to emit, since a key that exists in the schema and cannot be
  generated is absent for most benches in practice.
- Where the verdict is recorded. It is currently data that exists nowhere, which the metadata
  topic addresses; the two must agree.

## What is not in scope here

The benchspace layout, the sweep concept, and the naming. Those have their own topic file. The
metadata record is adjacent and its topic file states the coupling: whatever verdict semantics
this round settles on, the verdict itself becomes a field rather than a line on stderr.
