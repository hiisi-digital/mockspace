# Topic: a durable git gate that survives target cleans

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `bootstrap.rs` hook installation and `activate`. New home-config fallback hooks; `core.hooksPath`
retargeted; a locator git-config key.
**Motivation:** op, 2026-07-19. The generated git hooks live at `mock/target/hooks/` and `core.hooksPath`
points there, so `rm -rf target/` deletes the hooks directory and git silently runs nothing. Verified live:
vehje took an ungated commit this session for exactly this reason. A gate that a routine `cargo clean`
disables is not a gate.

## Current state, verified

`core.hooksPath` is set to `generated_hooks_dir(mock_dir)` = `<mock>/target/hooks/` (`activate`,
`src/bootstrap.rs:252`). The generated hook runs `cargo mock ...`, which is the alias
`run --manifest-path target/mockspace-proxy/Cargo.toml ...` (`ensure_cargo_alias`, near `:334`). So a
`target/` clean removes both the hooks directory git reads and the proxy the hooks invoke. Neither is
durable; both regenerate only when `build.rs` runs the bootstrap again (a `cargo check`/`cargo build` in
`mock/`).

## Decision

**A durable fallback hook lives in the user config directory, and `core.hooksPath` points at it.**

Location: `<config>/mockspace/hooks-v<HOOK_VERSION>/{pre-commit,pre-push}`, where `<config>` is
`$XDG_CONFIG_HOME` when set, else `$HOME/.config`. Version-keyed so several mockspace versions coexist and an
upgrade never clobbers an older repo's gate. Written by every bootstrap; idempotent by fingerprint like the
existing generated hooks.

`activate` sets `core.hooksPath` to that home directory instead of `<mock>/target/hooks/`, and writes
`git config --local mockspace.mockdir <mock_rel>` so the generic home hook can locate this repo's live
validator. Both git-config writes are already covered by the sudo ownership repair (`.git/config` is a
repair root as of round `202607190931`).

**The home hook self-heals, then blocks.** On each invocation it:

1. resolves the repo via `git rev-parse --show-toplevel`; refuses (exit 1) if not in a repo.
2. reads `mockspace.mockdir` (default `mock`) and forms `<root>/<mockdir>/target/hooks/<name>`.
3. if that live validator is executable, `exec`s it (the real gate runs, unchanged).
4. if missing, attempts self-heal: `cargo check` in `<root>/<mockdir>` triggers `build.rs`, which
   regenerates the proxy and the generated hooks. This is safe inside a commit because `bootstrap::run` does
   not touch `Cargo.lock` (only the non-lint-only interactive path calls `ensure_mockspace_current`).
5. if the validator is present after self-heal, `exec`s it.
6. otherwise blocks: exit 1 with the exact restore command and "ALL COMMITS BLOCKED until restored".

Op's explicit choice (2026-07-19) is self-heal-then-block, accepting that a commit may compile briefly while
the proxy rebuilds, in exchange for automatic recovery from a routine clean.

## Coverage and residuals

Covers: human and agent commits from a terminal, after a `target/` clean, in a repo bootstrapped at least
once. The home hook cannot be deleted by a repo-local clean.

Residual, accepted and unchanged: a fresh clone has `core.hooksPath` unset (local config is not cloned), so
git uses `.git/hooks` until the first build re-bootstraps. `--no-verify` still bypasses; no client hook can
close that. The agent-side gate (round B) is the belt to this suspenders for agent-driven commits when
`core.hooksPath` is unset.

## Not in scope

The agent-hook durable check (round B). The proxy staying under `target/` (self-heal rebuilds it; moving it
out of `target/` is a larger change with no additional durability once self-heal exists).
