# Why this round exists

#615 ported the file-size lint's line-count metrics (0..=2, over source bytes) and deferred the item-count metrics (3..=5) as "AST, bucket-2". This slice resolves that deferral and is the FIRST bucket-2 port, so it sets the pattern every subsequent bucket-2 (AST) lint follows: walk the flat `NamNode` array, navigate the tree without a sibling pointer, and read identifier / keyword text from source byte spans.

The #617 task names lints (export-count, no-empty-crate, tree-sitter no-todo) that do not exist in the catalog (the same memo-vs-catalog drift seen in #615); see the DOC CL for the corrected scope. "export-count" is exactly the file-metric `PubItemCount` metric, so it lands here.

# What lands

`file_size_evaluate` gains metrics 3..=5: `item_metric` walks `nam_file_nodes`, counts top-level item nodes, and detects `pub` visibility from source byte spans. The other AST lints (ast-type-position, ast-node-position) are deferred (they need viola-side `node_kind` table additions); see the DOC CL. Unit tests run against synthetic `NamNode` arrays.
