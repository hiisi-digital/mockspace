# mock-directory-in-custom-refs

The first step of the job `move_the_mock_directory_and_the_registry_into_custom_refs`. The probe and the reasoning are in the workspace note `.shared/research/202611031000_custom-refs-probe/NOTES.md`; this topic holds what the mockspace tree already has, and the cut of the step that remains.

## What dev already has

`mockspace-store` has `RefStore` (a delta as a commit on the tip, a push under a lease, a merge hook on a lost race), `Instance` (a directory kept in step with a ref's tip, its base kept in the common git directory, excluded from the branch's status) and the pairing record (`pairing.rs`, `pairing_ref.rs`). The registry mounts any directory of `<mock>/registry/` on a ref through `[[registry.store]]` (`src/registry/stores.rs`, `RegistryStores::from_decls`), and test history does the same through `[test.history]`. Both take a `RefDecl`.

What it lacks: a way for the mock directory outside the registry to live on a ref, an instance placed on disk from a declaration, and the verbs that keep instance and ref in step.

## The cut

A `[[data_ref]]` table in `mockspace.toml` (`[ref]` is taken), one entry to a ref, each opened through a `RefDecl` (so it reads with the same strictness) plus `path`, the one directory of the mock directory the ref holds as its root, and `instance`, where it is placed (default: in place, under the mock directory). Absent means none, so no consumer changes until it opts in.

Verbs, in the launcher: `cargo mock refs status` (each ref: tip, base of the instance, changed files, pairing), `refs instantiate` (materialise a tip into its instance), `refs commit` (apply the instance as an edit), `refs verify` (the recorded pairing resolves, the instance equals its base plus the declared edit). A missing instance is a loud error in every reader and never an empty tree.

## Defaults taken

The instances go in place for step one. Active round files stay in the trunk; closed archives go to the rest ref. The branch form is the remote default because the cloud proxy refuses `refs/mock/*` pushes.

## Not in this step

The `Mock-Ref` trailer at a landing, the stand-up fetch line, and the amendment to op for the tenets that name the trunk as where registry changes land. Each is its own piece after the table and the verbs stand.

## Owed to this topic

The write leg through a real remote wants a repository that may take a probe ref (coord or op). The order inside the step is the table and its parse, then `status` and `instantiate`, then `commit`, then `verify`.

## Amendment: what stands after the first step

The verbs are `cargo mock data-refs status|instantiate|commit|verify`, not `refs`. `status` fails for a declared ref with no instance and says to `instantiate` it; `verify` fails on a missing instance or on a changed file; both read the instance, never an empty tree. The pairing and the `Mock-Ref` trailer are still the later step named above.

Refused at parse: a `path` under a store mockspace keeps for itself (`registry`, `design_rounds`, `test-history`), two refs whose paths or instances overlap, and a namespace a registry store or the test history writes. The probe behind this topic is kept in the workspace research (`custom-refs-probe`), not in this repository.

The probe is now committed at `mock/research/sketches/custom-refs-probe/` (`FINDINGS.md` and `p0-local.sh`), and that copy is the evidence this topic rests on; the workspace-research path cited above is the same text. Correcting "Defaults taken": closed archives do not go to a rest ref in this step. `design_rounds` is refused as a `path` and as an `instance`, so the rest of the mock directory is reachable only as one ref per directory, which is narrower than "the rest of mockspace in another tree in the same shape as now" and stays owed.
