# A round cannot carry a merge, and the gates are why

**Date:** 2026-08-24
**Phase:** TOPIC

## What was found

Merging a trunk into a feature branch is impossible inside a design round, in
every repo that uses mockspace, and has been since the phase gates were written.

The mechanism is simple enough that it is easy to miss. A merge stages whatever
the two sides changed. In any branch that has been open more than a few days
that spans doc templates and source at once. `changelist-doc-gate` permits doc
templates only in DOC; `changelist-required` permits source only in IMPL. No
phase permits both, so the merge commit is refused whatever phase the round is
in, and closing the round does not help because CLOSED permits neither.

The three ways past it are all bad. Rebasing the branch replays every commit
against the moved trunk and re-resolves the same conflict once per commit, which
on a sixty-eight commit branch is not a merge conflict, it is sixty-eight of
them. Bypassing the hook with `--no-verify` is what the gates exist to prevent.
Opening a round to carry the merge fails on the same wall the merge hit.

It was found by hitting it: a consumer repo's feature branch could not take its
own trunk, and all three routes were tried before the cause was located.

## What the gates are actually for

They judge **authored** changes. Somebody opened a file, typed, and staged the
result, and the round ceremony is what says that was permitted. That reading is
correct for a commit somebody wrote and has nothing to say about a merge, where
git assembled the content and no author was involved.

So the gap is not that merges should be exempt. It is that a merge stages two
different kinds of thing at once and the gates could not tell them apart.

## The distinguisher, which is content

A file the merge resolved by taking one side is byte-identical to that side.
Nobody wrote anything, and the round ceremony has nothing to say about it.

A file somebody resolved by hand matches neither parent. That **is** an authored
change, it is exactly the kind the gates hold, and it should stay held.

The test is therefore per file, and it is a comparison of object ids: the staged
blob against the same path in each merge parent. Equal to one of them means
inherited. Equal to none means authored. A path absent from the index compares
equal to a parent that also lacks it, which is the deletion case, where taking
the other side's removal authored nothing either.

## Why not simply skip during a merge

Because a hand resolution is a real edit, made under no round, and a blanket
skip would let an arbitrary amount of new source in under cover of a merge. The
resolution of a conflicted file is where somebody is most likely to write
something that was never reviewed on either branch, so it is the last thing to
excuse.

## Where it lands

`changelist_required`, `changelist_doc_gate` and `changelist_lock` all walk
through one function, `src_layout::changed_files`, so the filter goes there and
all three inherit it. The comparison itself is `lint_rules::merge`.

Only the staged walk is filtered. An unstaged or untracked file during a merge
was dirty before the merge started and is nobody's resolution.

Off a merge the cost is one `git rev-parse` that fails, since there is no
`MERGE_HEAD`, and nothing per file.

## What is now guarded

Ten tests, on real git fixtures rather than on parsed output:

- off a merge nothing is inherited, so an ordinary staged edit is still reported
- a file only trunk touched is inherited
- a conflict resolved with `--theirs` or `--ours` is inherited
- **a hand resolution matching neither parent is not inherited**, which is the
  one a blanket skip would have got wrong
- a deletion the merge brought in is inherited
- a path neither parent carries is not, so two absences do not read as a match
- the relative rev-spec reads the mock copy rather than the repo-root one
- and, at the walk: a merge staging both a doc template and source reports
  neither, while a hand-resolved file in that same merge is still reported

Three of them failed against the first implementation and located a real defect
in it, which is what makes the seven that passed worth anything.
