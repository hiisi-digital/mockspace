# The repository runs its own gates

mockspace gets a `mockspace.toml` at its root, and from then on the engine runs on this repository the way it runs on any other: `mock`, `mock tools` and `mock search` answer here, the index covers the tree, and a commit goes through the same hooks. Nothing in the config marks the repository as special. This topic records what the gates found the first time they ran here, and what each finding was settled with.

## The pin

Options weighed:

- A branch pin, `mockspace_branch = "dev"`, as every other repository has. The hooks and the lints are the engine at the trunk's head, and the working tree's own engine runs only when asked for with `--engine .`.
- A path pin to the working tree. The launcher has no such form: its pins are a version, a rev, a tag or a branch, and a fifth form for an engine beside the config is named as plausible in its manifest code and not built.
- A pin to a fixed revision. It holds the gates still while the trunk moves, and every change to a gate would need a second change to the pin before it applied here.

Settled: the branch pin. It is one mechanism for every repository, which is what `mock/research/202605191000_bootstrap-circularity.md` asked of self-hosting, and a change to the engine reaches this repository's gates when it reaches the trunk, as it reaches everyone's.

## The lint cdylib's dependency graph

`crates/mockspace-builtin-lints` is a workspace root of its own, taking the stack and `viola-plugin-abi` from git by branch, with no lockfile committed. arvo's `dev` no longer has the `arvo` package, so the graph does not resolve, and the push gate's `cargo deny` refuses every push of the repository on it. viola's `dev` names the same `arvo` package, so the crate cannot follow arvo by itself.

Options weighed:

- Move the crate onto arvo's new crates. Its types cross viola's vtables, which are built on the old `arvo`, so the two would not unify until viola moves.
- Pin each dependency to a rev in the manifest. viola's own specs still name `branch = "dev"`, cargo refuses a `[patch]` to the same source, and a second spelling of the source makes the two `arvo` crates the manifest's comment warns about.
- Commit the `Cargo.lock` that holds each dependency at the commit viola's own lock resolves, leaving the specs as they are. The graph resolves, `cargo deny` passes against the repository's `deny.toml`, the crate builds and its 50 tests pass.
- Take the crate out of the tree, or out of the gate. The build plan of the data-ref architecture still gives it work, and leaving a workspace root out of the deny gate is an exemption.

Settled: the lockfile, with a test at the repository root that every separate workspace under `crates/` holds each branch dependency at a commit. The crate moves to arvo's new crates when viola does.

## Two definitions the single-source lint calls one

`mockspace-core` and `mockspace-refnames` each seal a trait family with a trait called `Sealed`, and `mockspace-core` and `mockspace-config` each declare `SCHEMA_MAJOR: u32 = 1`. Each pair is two concepts that share a name: core seals its typestate markers and refnames its fold kinds, and one constant is the major version of a round manifest while the other is the major version of the config. Settled: each is named for what it is, `TypestateMarker` and `FoldKind`, `MANIFEST_SCHEMA_MAJOR` and `CONFIG_SCHEMA_MAJOR`.

## Types no design names

Twenty types in `mockspace-builtin-lints`, `mockspace-refnames` and `mockspace-test-fixtures` are named by no design document, and the build gate refuses that. Each of the three crates gets a `DESIGN.md.tmpl` that says what it is for and names each of its types.

## A design describing a crate that was replaced

`mockspace-config`'s `DESIGN.md.tmpl` describes the crate as it was extracted in round `202605131900`: a render-context `Config` and an `IntoMockspaceConfig` trait mapping a consumer's schema onto it. The crate was replaced by the v2 `mockspace.toml` schema of the v2 spec, §46, and the trait, its `MappingError` and the `InstallMode`, `AttributionConfig`, `MacroStyle` and `CommitStyle` types went with it; the design was left as it was. The spec is the design the crate is built to, so the document is stale, and it is rewritten to the spec's schema. Its `README.md.tmpl` and `BACKLOG.md.tmpl` are rewritten with it.

## The round left open since August

The bench consolidation round's doc changelist, `202608151545`, sat flat and unlocked in `design_rounds/` from 15 August, so once the gates ran, the repository was in its doc window and no source could change. Part of its design has landed since (`[benchspace] members`) and part has not (`CellRecord`). It is archived as `202608151545-abandoned/` with the engine's `archive`, which keeps the changelist whole; its three topics stay flat, since the engine takes a file into a round's archive only while it is that round's. Reopening it is moving the changelist back flat.
