# Topic: cargo mock must work from the repo root AND from the mock dir

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `ensure_cargo_alias` in `src/bootstrap.rs`. A second generated `.cargo/config.toml` under the mock
dir.
**Motivation:** op, 2026-07-19. `cargo mock` works from the repo root and fails from `mock/` (and vice-versa
is the recurring confusion). Verified: from `mock/` it errors `manifest path target/mockspace-proxy/Cargo.toml
does not exist`.

## Root cause, verified

The alias in `<repo>/.cargo/config.toml` is
`run --manifest-path target/mockspace-proxy/Cargo.toml -- --dir mock`. Cargo resolves `--manifest-path`
relative to the current working directory, before mockspace runs. From `mock/` that becomes
`mock/target/mockspace-proxy`, which does not exist (the proxy lives at `<repo>/target/mockspace-proxy`,
`ensure_proxy_crate`, `src/bootstrap.rs:409`).

The `--dir` half is NOT the problem: `resolve_mock_dir` (`src/entry.rs:797`) already resolves a relative
`mock` from `mock/` via its repo-root fallback (`find_repo_root_from_cwd`). Only cargo`s manifest-path
resolution fails, and mockspace cannot intercept it because it fails before mockspace is invoked.

## Decision

Generate a second `.cargo/config.toml` under the mock dir with a `mock` alias whose `--manifest-path` is
adjusted by the mock dir`s depth: `<..per-component>/target/mockspace-proxy/Cargo.toml`. Cargo merges config
from cwd upward and the closer file wins for the `mock` alias key, so:

- cwd = repo root (or a non-mock subdir): only the root config is in scope, root alias resolves
  `target/mockspace-proxy` correctly.
- cwd = mock dir: the mock-local alias wins, resolving `../target/mockspace-proxy` to `<repo>/target/...`
  correctly.

Verified empirically: with the mock-local config present, cargo picks up the `../target` path (the error
message`s path changes accordingly), confirming the merge precedence works.

The `--dir` argument stays the repo-root-relative mock path in both configs; `resolve_mock_dir` handles it
from either cwd. The depth prefix is computed from the mock path`s component count so a nested mock dir gets
the right number of `..` segments.

## Residual

Running `cargo mock` from a deeper subdirectory of the mock dir (e.g. `mock/crates/foo`) still resolves the
mock-local `../target` incorrectly. Not a case op raised; the two addressed cwds (repo root, mock dir) are the
recurring ones. A depth-robust fix would need a PATH-installed cargo subcommand, which forfeits the per-repo
version pinning the proxy exists to provide; out of scope.

## Not in scope

Moving the proxy out of `target/`. Switching to an installed `cargo-mock` binary.
