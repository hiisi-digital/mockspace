## D1: config-bytes wire format, fixed arm [LOAD-BEARING]

The locked decisions memo deferred the per-lint config-bytes wire shape to "the first config-carrying port". This is it. A no_std / no_alloc cdylib cannot parse TOML or serde, so config crosses pre-encoded.

**Picked**: two arms by config nature.
- **Fixed configs** (file-size: a metric discriminant + a threshold) ride a `#[repr(C)]` struct. The host encodes the per-lint TOML into the struct; the cdylib reads it back with a pointer cast (`read_unaligned`, no alignment assumption) when `config_len == size_of::<TheConfig>()`.
- **Variable configs** (e.g. a token list) ride a length-prefixed binary blob the cdylib walks by hand. That arm lands with the token-scan port; this slice only ships the fixed arm.
- **Empty config** (`config_len == 0`) is a no-op: the lint is present but not configured, emits nothing. Rationale: the cdylib is a pure function over its inputs and does not own config-presence policy; the host validates config upstream (in-process, `file_metric::instantiate_with` makes `metric` and `threshold` mandatory and rejects an unconfigured lint as a `ConfigError`), so an absent config at the cdylib boundary means the lint is simply not active for this invocation. This is NOT the same shape as no-todo (which carries no config at all); the no-op here is a deliberate host-owns-validation choice, not a default-scan fallback.

Both sides are mockspace-authored, so the byte layout is an internal contract, not a published wire format. A `config_len` that is neither 0 nor the expected struct size returns `AbiStatus::InvalidArg`.

**Op confirmation point**: the repr(C)-for-fixed / length-prefixed-blob-for-variable split is the load-bearing call. If op prefers a single uniform encoding (e.g. everything length-prefixed, or a per-lint discriminated union), this slice's fixed arm is cheap to rework.

## D2: bucket-1 scope correction (memo-vs-catalog drift)

The #214 priority memo named "file-size, actionable-errors, no-bare-pub" as bucket 1 (pure source-bytes). The catalog does not match:

- **file-size** maps to the `file-metric` primitive (`mockspace-rs/src/builtins/file_metric.rs`). Genuinely pure-bytes for its line-count metrics. Ported here.
- **"actionable-errors"** does not exist as any preset or builtin. Dropped.
- **"no-bare-pub"** maps to the `no-public-raw-field` preset, which uses the `ast-type-position` primitive (a parsed AST). It is a bucket-2 lint and ships with the NAM-v1.1.0 AST ports (#617), not here.

The genuine pure-source-bytes primitives are `file-metric` and `token-scan` (literal substrings). `content-regex` carries arbitrary regex and is not portable to a no_std / no_alloc cdylib without a matcher engine; it is deferred to a separate design. The corrected bucket-1 port set is file-size (this slice) plus a token-scan lint (next slice on #615).

## D3: line-count metrics only

`file_metric::Metric` has six variants. The three item-count variants (PubItemCount, PrivateItemCount, TotalItemCount) set `needs_syn_ast` and require a parsed AST, so they are bucket-2. The cdylib file-size provider handles only the three line-count metrics (LineCount, NonBlankLineCount, NonBlankNonCommentLineCount) and returns `AbiStatus::InvalidArg` for an out-of-range metric discriminant. Line splitting matches `str::lines()`.
