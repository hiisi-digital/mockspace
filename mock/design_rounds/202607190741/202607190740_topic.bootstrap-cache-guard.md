# Topic: bootstrap must not install into the cargo cache, nor as root

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `bootstrap_from_buildscript()` in the root crate's `src/bootstrap.rs`. Two new skip guards, no
behavior change for legitimate repo builds.

## The incident

Recurring root-owned build artifacts across consumer repos (vehje 1248 files, arvo 1855, ikiuni 295, in
four clusters: 2026-06-19, 06-22, 06-25, 07-01), plus 915 root-owned files inside `~/.cargo/git/checkouts/`
with patient zero at 2026-06-07. Each poisoned cache entry makes subsequent user-run builds fail with
`Permission denied`, for which sudo becomes the workaround, which poisons more. The cycle sustained itself
for six weeks and bricked `cargo mock` in three repos.

## Root causes, verified

**The bootstrap cannot tell a working repo from the dependency cache.** `bootstrap_from_buildscript()`
(`src/bootstrap.rs:86-109`) guards on two ancestor probes: `mockspace.toml` exists, and `.git` exists. A
cargo git checkout under `~/.cargo/git/checkouts/` satisfies both, because it ships the full repo tree and
is a real git checkout. Verified by inspection of `~/.cargo/git/checkouts/arvo-da1db1860201e542/5776b61/`,
which carried the complete bootstrap fingerprint: `target/mockspace-proxy`, `.cargo/config.toml` with the
`mock` alias, and generated hooks. So every downstream consumer compiling arvo (or any mockspace-adopting
crate) from a git dependency runs the bootstrap inside the shared cache and installs there.

**Sudo on the development machine preserves `$HOME`** (`env_keep+="HOME MAIL"` in sudoers), so any sudo-run
build uses the invoking user's `~/.cargo` and writes root-owned files into the user cache. This is the
amplifier that turned one sudo-run build into a poisoned shared cache.

## Decision

Two skip guards at the top of `bootstrap_from_buildscript()`, before any filesystem write, each extracted
as a pure, unit-testable predicate:

**Guard A: dependency-cache builds skip.** If the canonicalized `CARGO_MANIFEST_DIR` lies inside the
canonicalized cargo home (`CARGO_HOME` env, defaulting to `$HOME/.cargo`), the bootstrap prints a
`cargo::warning` naming the skip and returns. Predicate: `is_inside_cargo_home(manifest_dir, cargo_home)`,
pure over two paths, no env access inside.

**Guard B: sudo builds skip.** If `SUDO_USER` is present in the environment, the build is running under
sudo and any install would land root-owned in user-owned trees; the bootstrap warns and returns. Detecting
sudo via its own env marker requires no libc dependency and targets exactly the observed vector. A plain
root login without sudo (no `SUDO_USER`) is out of scope: it does not occur in this workspace's use, and a
genuine root-owned CI environment would be denied by an euid check that this decision deliberately avoids
buying a libc dependency for.

Ordering: guard A before guard B, so a sudo-run dependency build reports the cache-skip reason, which is
the more informative of the two.

Both guards are warn-and-skip, never error: the bootstrap is a convenience installer, and a skipped
bootstrap leaves the consumer building normally without hooks, which is the correct degraded state.

## Not in scope

The sudoers `env_keep+=HOME` configuration is machine state, op's to change, and is surfaced in the
incident record rather than fixed here.

Cleanup of already-poisoned trees is manual (`sudo` removal), performed by op alongside this round.

`src/bootstrap.rs` is 1933 lines against the 500-line file-size tripwire. Splitting it is real work and a
separate round; this round adds one guard block plus two predicates.

The determinism defect found in the same investigation arc (`render_design.rs` shelling out to `date -u`)
is a separate round.

## Tests

Per `catalogue-edge-cases-as-tests.md`, the predicates land with unit tests in the same round: manifest dir
inside cargo home (skip), outside (proceed), cargo home unset with HOME set (default applies), nested
checkout paths (skip), the repo's own working tree (proceed), and `SUDO_USER` present (skip).
