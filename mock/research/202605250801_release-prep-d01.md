## Release-cadence rule compliance

Cross-referenced against `~/Dev/clause-dev/.claude/rules/release-cadence.md`:

- "Every merge to `main` is a release. Every release carries a tag." Op runs the release PR + tag together.
- Tag shape: `0.0.0-d01`. Pre-release prefix is intentional; tools resolving the tag get the pre-release signal automatically.
- Merge shape: NOT squash. Release PR uses `--merge` so dev's per-feature history lands on main in full granularity.
- Tag placement: on the merge commit on `main`, annotated (`-a`), terse message ("Design merge d01" is fine).

The release PR shape per `branch-pr-flow.md`:

```bash
# Op runs this. Agent does not open PRs against main.
gh pr create --base main --head dev --title "release: mockspace v2 d01" --body "..."
```

After merge:

```bash
git checkout main && git pull
git tag -a 0.0.0-d01 -m "Design merge d01"
git push origin 0.0.0-d01
```

## Findings

### Things in good shape

- **README.md** present and current at repo root.
- **LICENSE** present (MPL-2.0 matching workspace policy).
- **No SHAME entries** silencing release-critical lints (verified `SHAME.md.tmpl` presence and content; nothing flagged as release-blocking).
- **Dev branch clean state**: `git status` shows no untracked or modified files (verified pre-memo).
- **Git history is the changelog**: 177 commits with conventional-shape subjects; the log is the audit trail.

### Things deliberately not done

- **CHANGELOG.md NOT created.** Per `release-cadence.md`: "a structured CHANGELOG.md may emerge per repo when the cadence stabilises." For the first release, git history is the changelog. Skipping CHANGELOG removes a maintenance surface that adds no value at this cadence.
- **Cargo version NOT downgraded** from `0.1.0` to `0.0.0`. Tags and cargo versions are independent identifiers. The cargo version is internal-package metadata; the tag is the release identifier per `release-cadence.md`. The package carries `publish = false` so no consumer ever sees the cargo version via crates.io. Leaving cargo `0.1.0` keeps internal version progression independent of the public tag cadence.
- **No release-readiness gate added to CI.** The mockspace lint gates already block bad merges into `dev`; an additional release gate would be ceremony without value for an op-driven release flow.
