# Review 1 of mockspace fix/pack-identity-by-content at f129858: do not merge

The branch fixes the cross-tree identity, but it replaces cargo's own freshness check (dep-info and mtimes, which track every file rustc reads) with a hand-assembled input list that misses some of them. Before it a stale build could not replay; after it, three cases replay a stale library, each reproduced by the reviewer. Reviewed against the store's own invariant, "a stale entry is unreachable and never wrong" (`src/custom_lints/built.rs:9-10`).

1. Correctness: a lint edited during the build is stored under the old content's identity. The identity is computed at `src/custom_lints.rs:230` from the lint files; `cargo build` reads them again at `:233`. Save a file in between and the new library is stored under the old identity (`built.rs:39-47`); undo the edit and the next run loads the edited library with no build. Reproduced: first load returned "after" for the identity of "before". Fix: compute the identity again after the build and keep nothing if it moved; the fuller fix is 2.

2. Correctness: files a lint pulls in are not in the identity. `of_generated_crate` (`identity.rs:210`) hashes only the top-level `<name>.rs`. Missed: `include_str!`/`include_bytes!`, `#[path] mod` files in subdirectories, any file below a directory named `target` at any depth (`identity.rs:109`), files behind a symlinked directory or an unreadable file, silently skipped (`:115`). Reproduced with `include_str!("probe_name.txt")` changed from "one" to "two": load returned "one". Fix: after a build, read cargo's dep-info for the cdylib (the `.d` file: every file rustc opened, plus `# env-dep:` lines), keep that list beside the library, and before loading re-hash it against the asking tree; the current digest can stay as the lookup key.

3. Correctness: the build profile and cargo config are left out. `flags_from_env` (`identity.rs:182`) reads only `RUSTFLAGS` and `CARGO_ENCODED_RUSTFLAGS`, and the profile is a fixed string (`:62`). Missed: `CARGO_PROFILE_RELEASE_*`, `CARGO_BUILD_RUSTFLAGS`, `CARGO_TARGET_<triple>_RUSTFLAGS`, `[build] rustflags` and `[profile.release]` in any reachable `.cargo/config.toml` or under `CARGO_HOME`, `RUSTC_WRAPPER`, `env!` reads. Reproduced: a lint branching on `cfg!(debug_assertions)` loaded again with `CARGO_PROFILE_RELEASE_DEBUG_ASSERTIONS=true` returned "rel" where "dbg" was right. Either fold these in, or make `build_cdylib` hermetic (strip the env, pin the profile with `--config`) so leaving them out is true by construction.

4. Tests, regression: `store::e2e::without_the_lock_the_same_race_loads_the_wrong_lint` (`src/custom_lints/store_e2e_tests.rs:173`) is now flaky, red in 5 of 10 runs on f129858 and green 3 of 3 on dev, because the kept library answers tree A from the warm-up and the race no longer happens reliably. Rework the control so the race runs on a cold identity. Run the suite with `--include-ignored` before posting ready.

5. Tests: the inputs are tested only at the hasher, never where they are collected. With the toolchain replaced by "" at `identity.rs:213` all 69 tests stay green; with the flags never read from the environment, green apart from 4. Add tests at `of_generated_crate` for each input. `the_same_inputs_give_the_same_identity` (`identity_tests.rs:26`) compares a computation with itself: delete it.

6. Correctness, low: the collector hashed for the identity is generated against `/lints` (`custom_lints.rs:654`), where `scan_lint_functions` finds nothing, so it is not the text that is built; generate from the real directory and substitute the path afterwards. The generated `Cargo.toml` is dropped wholesale (`identity.rs:144`): hash it with the paths normalised.

7. Drift: the tree digest reads untracked files in path packages (swap files, a stray `Cargo.lock`), which splits two trees of one commit (costs only a rebuild). Every run now does `cargo metadata` and a SHA-256 of every path package; measure that cost in kaski, and show kaski's two-tree case, which is the point of the job.

8. Public surface: `README.md:143` and `docs/USAGE_GUIDE.md:525` say nothing of the new `built/` directory or its 14-day sweep, and `USAGE_GUIDE.md:532` ("every loaded pack by content") wants "by its inputs". `src/custom_lints.rs` grows from 1387 to 1415 lines, well over 500: split it along its seams rather than grow it.

Verified sound: a registry or git package is identified by version and source and a path package by content relative to its root; the generated crate is left out; a failed build keeps nothing, writes are temp-and-rename, and the reap skips `built/`. Commit message clean. The reviewer's scratch tests for 1 to 3 are spikes: commit each as a red test in `identity_e2e_tests.rs` (load, change one input, load again, assert the new behaviour) before the fix.
