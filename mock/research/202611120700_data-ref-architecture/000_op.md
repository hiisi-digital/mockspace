## Answers to the consolidation, 2026-11-12

Q1 asked: every namespace at `git~1/<ns>` at the repository root, a path git refuses from any commit. Options: git~1 for all; git~1 only for the namespace that points back into the tree; ordinary names.

> What’s the trick with git~1, is it matching some existing filter in git, and is it the special char or the word git as whole before it? That shapes what other names we could figure. A .git~1 would be better but if it’s the whole git then won’t work. ~mock/ could work if it’s the special char but how cross platform is that? Also yes, we don’t want a mock/ dir literally anywhere in there; all things should just use mock://<ns>… kind of. Or plain <ignoredInstanceRoot>/<ns>. The mock/ dir convention is optional even today on mockspace and configurable via the config.

Q2 asked: where templates live. Options: into the data tree with the renderer resolving through one function; beside sources with the pattern machinery kept; on the code branch.

> Option 1, it goes to the data and refs, but something other than templates. I think we’ll want a @ dir if allowed or path resolving to that in there, so a @/crates/foo maps to just /crates/foo in the root of the actual public code tree. Let’s call that the git tree for consistency and the special refs together as mock trees even if separate. If one of them wants a bespoke name like registry tree, then definitely do that too ofc. But we want consistency in what we talk about and formalise them

Q3 asked: how the remote is guarded against `push --mirror`. Options: same repository, accept the window and probe hosts; a second repository; a server-side update hook.

> Well I mean couldn’t we just hook to —mirror calls ? If not, then unless it causes advancing head type of churn, we should just silently and automatically do the re-pushes of the trees. But what happens if the tree deletion or old copy is pushed that way and none of the local repos anywhere hold the true one? It’s lost? Also; second repo is only an optional alternative. Default to same repo custom refs.

Q5 asked: what ships of the `core.fsmonitor` pre-write copy. Options: off until benched; on; not shipped.

> Using git-shook should remove the clash. We can demand it for mocksoace use or auto-install and use it with mockspace. I would like it to be on but we should get a rough ballpark of its impact. If it’s just a sub second wait only on calling any git command, that’s fine but borderline. Anything below is smooth enough. Anything over is probably bad and especially if it’s a constant cost not only paid on the git commands

The intent:
- No literal `mock/` directory anywhere. A mock tree is addressed as `mock://<ns>` or `<ignored instance root>/<ns>`, and the instance root is configured.
- Templates and their kind go into a mock tree under `@`, where `@/crates/foo` maps to `/crates/foo` of the code tree.
- The code tree is called the git tree, and the data refs together are the mock trees. A bespoke name such as registry tree is welcome. The terms are formalised and used consistently.
- The data refs default to custom refs on the same repository; a second repository is an optional alternative.
- A destructive mirror push is caught by a hook where possible, else repaired by an automatic re-push that causes no churn, and the case where no clone holds the true tip must be answered.
- The pre-write copy ships on, through git-shook, provided its cost stays under about a second per git command and is not a constant background cost.

His questions about the name (is the refusal the word or the character, would `.git~1` or `~mock` work, how portable is it) are questions, answered by probe `011_probes/n1`.
