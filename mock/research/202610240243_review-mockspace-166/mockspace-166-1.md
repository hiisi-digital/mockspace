# Review of mockspace #166, first read: blocking findings

1. The bench digest ignores inputs outside `benches/`, so a broken bench passes (`src/entry/test_benches.rs:47-62`). Reproduced at the head: a bench crate with a path dependency on a member passed run 1; the member was changed so the bench assertion fails; run 2 printed `benches : not run (its inputs have not moved...)`, `1 tree(s) green`, exit 0; run 3 with `--benches` failed. On `dev` run 2 fails, so this is a regression. kaski's support crates do exactly this (`kaski/mock/benches/figure-crowd/support/crowd/Cargo.toml:13-18` to `../../../../crates/kaski-*`). The digest also omits the toolchain pin, `.cargo/config` and the lockfile, which the member fingerprint salts (`src/suite/fingerprint.rs:84-92`, `WORKSPACE_INPUTS`). Fix: add that salt and the directories of every local package reachable from the bench manifests, generated arm manifests and support crates from `bench_gen::plan` included; commit the reproduction as a test.
2. Generated outputs count as inputs: `src/bench.rs:140` calls `results/` and `history/` outputs, but `OUTPUT_DIRS` (`test_benches.rs:44`) skips only `target` and `.git`, so every `mock bench run` reruns every arm on the next `mock test`, and untracked junk does too; the USAGE_GUIDE "(build output aside)" is then untrue. Fix: the same tracked-or-would-track file list the members use (`fingerprint::tracked_files`), minus `results/` and `history/`.
3. The recorded digest is taken after the run (`src/entry/test.rs:281-287`), so an edit during the arm build is recorded green untested. Fix: digest before the run (lockfiles aside), record only if the after-run digest matches.
4. `the_digest_is_stable_over_an_unchanged_tree` (`test_benches_tests.rs:73-77`) compares a computation with itself and cannot fail (all 11 unit tests pass with `files.sort()` removed and `.git` dropped from `OUTPUT_DIRS`). Delete it; add an order-independence test of a pure digest over the file list fed reversed, and a `.git` exclusion test.
5. `decide()` has 12 cases (asked x named x record none/same/different) and 7 are tested. Write all 12.
6. The integration fixture is a hand-made flat crate (`tests/mock_test_benches_when_moved.rs:36-55`), not the generated-manifest layout `mock bench init` makes, against the brief's existing fixtures (`tests/mock_test_reaches_every_tree.rs:51`). Prove the skip and the rerun on the canonical layout, and cover findings 1 and 2.
7. The final summary does not name the skipped benches (`test.rs:311-313`); a benches-only run prints `0 tree(s) green` and exits 0. Put the skip and its reason in the final line.
8. Public surface: `src/entry/help.rs:273`, `docs/USAGE_GUIDE.md:123`, `README.md:114` still say only members are selective and do not mention `--benches`. The v1 builtin text (`src/render_agent/templates.rs:961-963`) needs revising with finding 1.

Non-blocking, take what is cheap: `help.rs:328` over-long line; the test doc comment "fails on the old code" misleads (dev already skipped benches under `-p`); a test-name filter or `-E` still runs the whole moved benches tree; `collect` follows symlinked directories, so a loop recurses without end.
