# Migrating agent infrastructure from v1 to v2

This guide covers what changes for downstream consumers who carried v1-style
agent template files (`MAIN.md.tmpl`, `PREAMBLE.md.tmpl`, `POSTAMBLE.md.tmpl`,
plus `agent/{skills,hooks,rules,settings}/`) and are picking up the v2
mockspace agent surface.

The lint migration is covered separately at
[MIGRATION-v1-to-v2-lints.md](MIGRATION-v1-to-v2-lints.md). This document is
the consumer-facing companion for the agent surface only.

## What changed

v1 mockspace shipped consumer-overridable agent files via a templating
engine. Each consumer crate carried its own `agent/MAIN.md.tmpl` (plus
preamble and postamble) and the template engine merged them into the
final agent context at bootstrap time.

v2 mockspace replaces the templated surface with **static markdown
fragments**. The fragments live in the binary (embedded via `include_str!`
under `mock/crates/mockspace-rs/src/agent_builtin/`) and extract to
`.claude/agent_builtin/` during `cargo mock install` or `cargo mock
refresh`. Routing between fragments is done via `INDEX.md` links rather
than via the template engine's `{{ include }}` syntax.

The functional outcome is the same: the agent reads one canonical body
of mockspace-specific guidance that lands at a known location on disk.
What goes away is the consumer's ability to substitute or override
fragments at bootstrap time.

## Migration map: v1 file to v2 fragment

| v1 file                   | v2 fragment                                                | Notes |
|---------------------------|------------------------------------------------------------|-------|
| `agent/MAIN.md.tmpl`      | `INDEX.md` + every linked fragment                         | The single entry-point. v2 splits the body across topical fragments; INDEX.md is the routing table. |
| `agent/PREAMBLE.md.tmpl`  | `identity.md`                                              | Project-wide framing (what mockspace is, what the agent does). |
| `agent/POSTAMBLE.md.tmpl` | `commands.md` + `suppressions.md`                          | Operational reference: what the agent runs and how it suppresses noise. |
| `agent/skills/<n>.md`     | (no direct equivalent yet)                                 | Per-skill files were a v1 extensibility surface. v2 ships skills inline within fragments; consumer-authored skills wait on the viola plugin runtime (tracked separately in the viola repo). |
| `agent/hooks/<hook>.sh`   | `mock/target/hooks/<hook>.sh` (post-install)               | Hooks now generated by `bootstrap_from_buildscript`; consumer hooks add on top of the generated set. |
| `agent/rules/<rule>.md`   | (no direct equivalent in agent_builtin)                    | Workspace rules now live at `.claude/rules/` and aggregate via homma rather than via mockspace; per-repo rules can still ship under each repo's `.claude/rules/`. |
| `agent/settings/*`        | Inferred from `mockspace.toml` + workspace configuration   | v1's freestanding settings tree retires; configuration moves into the canonical `mockspace.toml` schema. |

## What consumers gain

- **Faster bootstrap.** No template engine roundtrip; fragments
  extract verbatim.
- **Smaller dependency tree.** The v1 template engine dependency is gone.
- **Versioned per-fragment routing.** `INDEX.md` lives alongside the
  fragments and changes with them; routing drift cannot lag the content.
- **One canonical body.** Consumers stop maintaining their own copies
  of mockspace-specific framing; they read whatever mockspace ships
  with the binary they installed.

## What consumers lose, with workarounds

- **Per-fragment override.** v1 consumers could replace
  `agent/PREAMBLE.md.tmpl` with their own version. v2 has no per-
  fragment override mechanism. Workaround: write project-specific
  framing in the consumer's own `.claude/` tree alongside the
  mockspace fragments; the agent reads both.
- **Custom skills.** v1 consumers shipped per-skill `.md` files. v2
  embeds skills inline. Workaround: track per-project skills in the
  consumer's `.claude/skills/` until viola plugins land (tracked in
  the viola repo).

## Migration steps

1. Run `cargo mock install` (or `refresh`) in the consumer crate. This
   extracts the v2 fragments to `.claude/agent_builtin/` and writes
   `INDEX.md`.

2. Remove the v1 tree:

   ```bash
   rm -rf agent/MAIN.md.tmpl agent/PREAMBLE.md.tmpl agent/POSTAMBLE.md.tmpl agent/skills/ agent/settings/
   # agent/hooks/ and agent/rules/ may or may not have v1-specific content; review before removing.
   ```

3. If the v1 tree carried project-specific overrides (custom skills,
   custom preamble), copy those into the consumer's own `.claude/`
   tree. The mockspace fragments at `.claude/agent_builtin/` and the
   consumer's `.claude/` tree are both read by the agent.

4. Update any consumer docs that referenced the v1 tmpl files. The
   new home for "what does the agent know about mockspace" is the
   `INDEX.md` at `.claude/agent_builtin/`.

5. Verify with `cargo mock status`: the adoption signal carries
   "agent surface installed" once the fragments are in place.
