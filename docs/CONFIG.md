# mockspace-config

The typed schema of the v2 `mockspace.toml`, as section 46 of the v2 specification lays it out, and the parser that reads a file into it. A tool that reads or writes a mockspace config takes it from here, without depending on the engine.

A key the schema does not refuse is dropped without a word, typo or not, so where it refuses one matters. The root of the file is strict: a key it does not have, a retired section among them, is an error at parse time naming the key. So are the inline form of an import and a preset file. The sections under the root, `[mockspace]`, `[refs]`, `[hosts.<name>]` and the rest, are not checked, and an unknown key inside one parses and is dropped. A `[lints.<name>]` table keeps the keys it does not name, for the lint to read.

## What this crate provides

| Item | Role |
|---|---|
| `Config` | The whole file: each section below as a field, defaulted where the section is absent. |
| `MockspaceSection` | `[mockspace]`: the schema version, the default profile, whether one round is active at a time, the verifier timeout, and `mock_bin_path`. |
| `RefsSection`, `RefsSecuritySection` | `[refs]` and `[refs.security]`: the ref-storage policy, and the controls on importing a ref (the domains allowed, https required). |
| `HostSection`, `ForgeKind`, `MergeStyle` | `[hosts.<name>]`: one schema for every host. The primary host, named by `primary_host`, fills in the forge integration; the others are sources to import or mirror from. |
| `ImportsSection`, `ImportEntry`, `TypedImport`, `ImportKind`, `ExtImport` | `[imports]`: the static ref imports and the per-host extensions, each import carrying the trust tier its verification follows. |
| `LintCrateRef` | `[lint-crates.<name>]`: an external lint pack. |
| `LintConfig`, `ScopedLintConfig`, `Severity`, `GateSeverities` | `[lints.<name>]` and its scoped overrides: a severity at each gate, and an `extends` naming a preset. |
| `PresetFile` | A preset's own file: what it extends and the severities it sets. |
| `LanguageEntry`, `BuiltInLiteral`, `LanguageHost` | `[languages.<lang>]`: `"built-in"`, or the git host a language's support comes from. |
| `ProfileSection`, `OnDirtyState` | `[profile.<name>]`: the policy a profile applies, section 36 of the specification. |
| `CrateColor`, `DomainKind`, `KnownMacro` | `[crate_colors]`, `[domain_kinds]` and `[known_macros]`: open-ended display metadata. |
| `TransparencySection`, `UndoSection` | `[transparency]` and `[undo]`: the optional transparency log, and how long the undo log is kept. |
| `parse_mockspace_toml`, `parse_mockspace_toml_str` | Read a file, or a string, into a `Config`. |
| `CONFIG_SCHEMA_MAJOR` | The major version of the schema this parser reads. A file's version is matched on its major part. |
| `ConfigError` | What parsing fails with: the file could not be read, the TOML did not parse into the schema, or a value failed validation. |
| `PresetRef`, `parse_preset_shorthand`, `resolve_preset_chain`, `PresetSource`, `PresetResolveError` | Presets: the `<host>::<name>` shorthand parsed into a reference, and the chain of `extends` resolved through a source of presets, refusing a cycle and a preset the source does not have. |

## What this crate does not do

| Concern | Where it lives |
|---|---|
| Rendering a template against the config | `mockspace-template` |
| Fetching an import, verifying its signature, or reading a ref | the engine |
| Running a lint at the severities set here | the engine and the lint packs |

## Crate dependencies

- `serde` and `toml`, for the schema and its parsing.
- `letkajenkka`, the one parser of a reference path, and `mockspace-refnames`, for how mockspace folds and reads the names in one.
